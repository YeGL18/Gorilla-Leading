# Parking UI and native visit follow-up

These changes build on the local `ours/next` work, preserving the prior map performance and floor capture changes.

- Boundary drawing uses the existing address capsule's glass surface and spring transition instead of a separate material toolbar. Entry raises the minimum camera distance from 450 to 1200 metres and interpolates from the current camera over 0.9 seconds. Dismissing the source parking popup no longer cancels that flight. During entry, map gestures and drawing controls are locked; the drawing canvas and coordinate provider are created only after the camera reaches the lot center, distance, north heading and flat pitch. Portrait map/search/heading buttons rise by the drawing capsule’s additional height (including an invalid-shape hint) using their existing offset animation, and return when cancelled. The canvas fades in over 0.38 seconds, coordinated with animated toolbar tint changes; hit testing becomes available only once the camera has arrived. Cancel remains available. Session IDs and a dedicated flight timer prevent a cancelled or replaced flight from re-enabling editing. Source popup range overlays are removed during drawing entry.
- Map entry keeps one in-progress tracking flight when appearance/orientation signals overlap. GPS-driven tracking and heading updates wait for the initial flight to finish. The first flight starts from the existing camera instead of resetting it to 50 km again. Initial map frame/center offsets are applied without an entrance frame animation; later capsule offset changes retain their existing transition. Tracking flights scope camera-write permission to every frame, so layout updates cannot lock the remaining animation. Delayed tracking handoffs ignore cancelled/replaced flights.
- Parking-marker dragging owns annotation selection throughout dragging and deceleration. Selection stays suppressed after settlement until a new touch, preventing a delayed release over a meter from opening its popup. Both programmatic selection and native delegate callbacks are guarded, and deselection cannot restore a competing selection during that gesture. A later touch selects meters normally.
- Merge rows use primary text, secondary metadata, and a teal symbol. The entire row remains tappable with the plain button style.
- Stay points expose no effective/display floor or confirmation state. Their popup, history rows, diagnostics and floor grouping omit parking floor controls. Raw historical floor fields remain stored so reclassifying a point does not erase its previous value.
- Destination search retains the first category menu and second anchored popup. The second popup contains a bounded scrolling list and explicitly uses popover presentation in compact layouts, rather than a sheet.
- The application delegate creates the shared location receiver at launch, including locked background launches. Protected preferences are hydrated before pending events can be merged. Native visit events are buffered in an atomic file with protection until first user authentication. Departures with an unavailable arrival timestamp match an existing visit, or remain queued for an out-of-order arrival. Native long stays no longer disappear behind an arbitrary seven-day cutoff. GPS matching uses reported horizontal accuracy for near-identical arrivals. Visit geocoding cannot cancel live-address geocoding or resurrect a deleted visit.

Apple documents that visits may omit arrival information, and that a background relaunch needs a recreated location manager and delegate: [CLVisit](https://developer.apple.com/documentation/corelocation/clvisit), [startMonitoringVisits](https://developer.apple.com/documentation/corelocation/cllocationmanager/startmonitoringvisits()). The installed SDK's CLVisit.h specifies distantPast/distantFuture sentinels.

Validation:

- `ruby Tests/VisitHistoryChecks.rb`: native timestamp sentinels, accurate/ambiguous GPS matching, return visits and long stays, plus existing history checks.
- `ruby Tests/VisitEventChecks.rb`: extracted production event/queue methods with isolated storage. Locked process restart, hydration ordering, original record IDs, departure before arrival, a second lock, and a 15-day stay.
- `ruby Tests/ParkingLevelChecks.rb`: stay points cannot expose a floor; prior floor, capture, grouping, storage and area checks pass.
- SettingsSearch UI tests on an iPhone 16 Pro / iOS 26.1 simulator: portrait and landscape reach/select item 50, and the category-to-popup selection works without a sheet.
- ParkingPresentation UI tests: production drawing camera methods retain continuity when the source popup closes, reach the higher target, and restore gestures on exit; delayed canvas/coordinate access, disabled editing controls until arrival, repeat entry and cancellation during flight are checked; production toolbar cancellation and merge selection/confirmation pass. Screenshots verify neutral merge text and the existing glass capsule style. The presentation fixture isolates these components rather than running the full app.
- Map entry regression: repeated tracking requests and a camera-permission reset during layout fail with the previous extracted production methods, and pass after the fix. Boundary UI regression also checks an intermediate presentation-layer opacity before the canvas reaches full opacity.
- Early-GPS startup regression uses the production driving display-link, flight, initial-camera and frame-layout methods. It checks no driving link or camera movement before entry, no upward distance reversal during the flight, no flight restart on a repeated trigger, and the handoff to driving tracking after arrival.
- Portrait toolbar checks cover the drawing capsule, its extra invalid-boundary hint, three tappable map controls above the capsule, and return to the compact offset. The controls share the capsule’s entry spring and hint-height animation.
- Drag selection checks use a real MapKit view and the production selection guards: native and programmatic meter selection are blocked during dragging, coasting and a delayed release, then succeed on the next touch. This isolates event routing; physical finger dragging still needs a device check.
- The app and widget compile and sign for the physical iPhone 16 Pro.

Real system delivery during a driving trip still requires a device road test. Historical departure timestamps that were never retained cannot be reconstructed without a real native event; no departure time is invented from a later arrival.
